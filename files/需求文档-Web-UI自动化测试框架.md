## 1. 项目概述

### 1.1 项目背景

- 电商核心链路（登录、筛选加购、购物车结算、订单确认）重复手工回归耗时大、易遗漏。
- 前端频繁改版导致元素定位变更，脚本维护成本高。
- 页面异步加载、弹窗遮挡、元素定位漂移等线上高频问题导致自动化脚本不稳定。

### 1.2 项目目标

- 基于 Python + Selenium + pytest 搭建电商 Web UI 自动化测试框架，采用 PO 分层架构解耦。
- 覆盖电商核心链路冒烟测试：登录 → 商品筛选 → 加购 → 购物车结算 → 订单确认。
- 替代重复手工回归，缩短回归周期，提升测试效率。
- 页面元素统一维护：前端改版时只需修改页面层定位信息，用例脚本无需改动。
- 提供失败自动截图、运行日志、显性等待公共方法，提升脚本运行稳定性。

### 1.3 项目范围

- **范围内**：电商 Web 端核心链路 UI 自动化（冒烟级别）；框架搭建、公共能力封装、用例编写与稳定性调优。
- **范围外（可后续扩展）**：接口自动化、性能测试、移动端测试、跨浏览器矩阵测试、CI/CD 流水线集成。

## 3. 架构设计（PO 分层）

### 3.1 分层结构

| 层次 | 职责 | 说明 |
| --- | --- | --- |
| 页面层（Page） | 元素定位 + 页面操作 | 每个页面一个 Page 类，元素定位信息集中维护，不包含业务逻辑 |
| 业务操作层（Business） | 业务动作组合与封装 | 组合多个页面操作形成可复用业务动作（登录、加购、结算等） |
| 用例层（TestCase） | 测试场景与断言 | 只调用业务操作层，只关心"做什么"，不关心"怎么做" |

**依赖方向**：用例层 → 业务操作层 → 页面层（单向依赖，逐层解耦）

### 3.2 分层收益

- 前端改版：仅修改页面层定位信息，业务层与用例层零改动。
- 业务变更：仅调整业务操作层，用例层不变。
- 用例可读性高：用例即业务场景描述，非技术人员可读。
- 公共能力下沉：BasePage 统一封装点击、输入、等待、截图、滚动等基础能力。

## 4. 功能需求

### 4.1 分层架构

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-01 | 页面层：每个页面独立 Page 类，元素定位信息统一维护（元素名 + 定位方式 + 定位表达式） | 高 |
| FR-02 | 业务操作层：业务动作原子化、可复用（登录、搜索筛选、加购、结算、提交订单等） | 高 |
| FR-03 | 用例层：用例仅依赖业务操作层与断言，不直接接触元素定位 | 高 |
| FR-04 | BasePage 基类：封装公共操作（点击、输入、显性等待、滚动、截图） | 高 |

### 4.2 核心链路覆盖

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-05 | 登录流程：输入账号密码、点击登录、校验登录成功（页面跳转 / 欢迎语） | 高 |
| FR-06 | 商品筛选：关键词搜索与筛选条件组合、校验搜索结果 | 高 |
| FR-07 | 加购：进入商品详情、选择数量/规格、点击加购、校验加购成功提示 | 高 |
| FR-08 | 购物车结算：校验购物车条目与数量、修改数量、点击结算 | 高 |
| FR-09 | 订单确认：确认收货地址与商品信息、提交订单、校验下单成功 | 高 |
| FR-10 | 冒烟套件：核心链路用例汇总为冒烟套件，支持一键运行 | 高 |

### 4.3 稳定性保障

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-11 | 显性等待公共方法：基于 WebDriverWait + expected_conditions 封装（元素可见、可点击、存在、消失、文本出现），超时与轮询间隔可配置 | 高 |
| FR-12 | 异步加载处理：操作前等待加载完成（loading 消失、元素就绪） | 高 |
| FR-13 | 弹窗遮挡处理：识别并处理 toast、广告弹窗、Cookie 弹窗等（关闭或等待消失） | 高 |
| FR-14 | 元素定位漂移处理：优先使用稳定属性（id、data-*），支持多级定位策略（主定位 + 备选定位） | 中 |
| FR-15 | 失败自动截图：用例失败时自动截图保存至指定目录，命名含用例名与时间戳 | 高 |
| FR-16 | 运行日志：分级日志（INFO/ERROR）保存至日志目录，记录操作步骤、定位信息、失败堆栈 | 高 |

### 4.4 配置与扩展

| 编号 | 需求描述 | 优先级 |
| --- | --- | --- |
| FR-17 | 配置文件：浏览器类型、headless、等待超时、基础 URL、账号等集中管理 | 高 |
| FR-18 | 测试数据与脚本分离：账号、商品关键词等数据独立管理，支持参数化 | 中 |
| FR-19 | 测试报告：生成 HTML/Allure 报告，展示通过率、失败原因与截图 | 中 |
| FR-20 | 命令行一键运行：支持 pytest 命令行/脚本方式运行冒烟套件（为后续接 CI 预留） | 中 |

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 稳定性 | 核心链路冒烟用例在稳定环境下通过率 ≥ 95% |
| 可维护性 | 前端改版时 90% 以上的脚本无需改动，仅修改页面层定位信息 |
| 可扩展性 | 新增页面/业务时，只需新增对应 Page / Business 类，不修改既有用例 |
| 可读性 | 代码遵循 PEP8，命名语义化、统一规范，注释说明关键逻辑 |
| 执行效率 | 冒烟套件整体执行时间控制在 10 分钟以内（视用例规模） |
| 容错性 | 失败自动截图留证、日志可回溯，支持失败重试机制（可选） |

## 7. 用例设计（示例）

| 编号 | 用例名称 | 前置条件 | 关键步骤 | 预期结果 |
| --- | --- | --- | --- | --- |
| TC-01 | 登录成功 | 测试账号可用 | 打开首页 → 登录 → 输入账号密码 → 提交 | 进入登录态页面 |
| TC-02 | 搜索与筛选加购 | 已登录 | 搜索关键词 → 应用筛选 → 进入详情 → 加购 | 加购成功提示出现，购物车数量 +1 |
| TC-03 | 购物车结算 | 购物车有商品 | 打开购物车 → 校验条目 → 结算 | 跳转订单确认页 |
| TC-04 | 订单确认 | 已进入结算页 | 确认地址/商品 → 提交订单 | 下单成功页面出现 |
| TC-05 | 全链路冒烟 | 测试账号可用 | 登录 → 筛选加购 → 购物车结算 → 订单确认 | 全链路各步骤校验通过 |

> 说明：登录失败提示、非法输入、边界场景等负向用例作为扩展补充，不纳入冒烟套件（可选）。

## 8. 验收标准

1. 框架符合 PO 三层分层架构，依赖方向单向清晰。
2. 核心链路冒烟用例（TC-01 ~ TC-05）全部可运行，稳定环境下通过率 ≥ 95%。
3. 用例失败自动截图且日志完整落地，可回溯失败原因。
4. 验证可维护性：模拟前端元素变更，仅修改页面层定位信息后，用例脚本无需改动即可通过。
5. 公共等待方法覆盖可见、可点击、消失等常用场景，异步加载与弹窗场景运行稳定。
6. 提供 README 使用文档：环境准备、安装步骤、运行命令、目录说明。

## 10. 风险与应对

| 风险 | 应对措施 |
| --- | --- |
| 目标站点改版频繁 | 元素统一维护 + 多级定位策略 + 优先稳定属性 |
| 验证码 / 风控拦截 | 使用测试环境固定账号，预留人工处理或跳过策略 |
| 页面异步加载慢 | 显性等待 + 合理超时配置 + 失败重试 |
| 弹窗随机出现 | 公共弹窗处理封装，统一识别与关闭 |
| 测试环境不稳定 | headless 模式、重试机制、截图留证、日志回溯 |
